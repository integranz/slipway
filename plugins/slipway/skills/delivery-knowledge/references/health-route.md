# Health route convention — what every deployable app must answer (added 2026-10-27)

slipway's deployment contract needs one HTTP endpoint per app that answers `200` and reports the running version: the Container Apps probes use it, `/slipway:verify` compares its `version` with the deployed image tag, and the smoke test waits on it. Curated stacks (`dotnet8-api`, `react-vite`) already have it. For `stack: custom` apps **without** a health route, the agent adds one when the framework is recognised below, in the same change as the Dockerfile; the health path then is `/health` and is not a missing value. Only an unrecognised framework stops the bootstrap with "health path needed".

Rules of the route: path `/health`; method GET; status `200`; JSON `{"status":"ok","version":"<VERSION>"}` where the version is read **at request time** from the `VERSION` environment variable (the Dockerfile stamps `ARG VERSION` into `ENV VERSION`; fall back to `0.0.0-local`), no caching (`Cache-Control: no-store`), no authentication, no call to a backend or a database (liveness of this process only; a dependency outage must not restart the container). Keep it out of auth middleware and router prefixes.

| Framework (detected by) | Where | Snippet |
|---|---|---|
| Next.js app router (`next` dependency, `app/` directory) | `app/health/route.ts` | `import { connection } from "next/server"; export async function GET() { await connection(); return Response.json({ status: "ok", version: process.env.VERSION ?? "0.0.0-local" }, { headers: { "cache-control": "no-store" } }); }` — `connection()` makes it dynamic so the value is read in the container, not at build. If a `proxy.ts`/`middleware.ts` redirects unauthenticated requests, exempt `/health` by exact match |
| Next.js pages router (`pages/`) | `pages/api/health.ts` and `health_path: /api/health` | `export default function handler(_req, res) { res.setHeader("cache-control", "no-store"); res.status(200).json({ status: "ok", version: process.env.VERSION ?? "0.0.0-local" }); }` |
| Express / Koa / Fastify / Hono (`package.json` dependency) | before the routers and auth middleware | Express: `app.get("/health", (_req, res) => res.set("cache-control", "no-store").json({ status: "ok", version: process.env.VERSION ?? "0.0.0-local" }));` Fastify: `app.get("/health", async (_req, reply) => reply.header("cache-control", "no-store").send({ status: "ok", version: process.env.VERSION ?? "0.0.0-local" }));` |
| FastAPI / Flask (`pyproject.toml` / `requirements.txt`) | the app module | FastAPI: `@app.get("/health") def health(response: Response): response.headers["cache-control"] = "no-store"; return {"status": "ok", "version": os.environ.get("VERSION", "0.0.0-local")}` Flask: `@app.get("/health") def health(): return jsonify(status="ok", version=os.environ.get("VERSION", "0.0.0-local")), 200, {"Cache-Control": "no-store"}` |
| ASP.NET Core minimal API or MVC (`*.csproj` with `Microsoft.NET.Sdk.Web`) | `Program.cs` | `app.MapGet("/health", (HttpResponse r) => { r.Headers.CacheControl = "no-store"; return Results.Ok(new { status = "ok", version = Environment.GetEnvironmentVariable("VERSION") ?? "0.0.0-local" }); });` (the curated template does this already) |
| Go `net/http` (`go.mod`) | the mux | `mux.HandleFunc("GET /health", func(w http.ResponseWriter, _ *http.Request) { w.Header().Set("Cache-Control", "no-store"); v := os.Getenv("VERSION"); if v == "" { v = "0.0.0-local" }; json.NewEncoder(w).Encode(map[string]string{"status": "ok", "version": v}) })` |
| Spring Boot (`pom.xml`/`build.gradle` with `spring-boot-starter-web`) | a `@RestController` | `@GetMapping("/health") public ResponseEntity<Map<String,String>> health() { return ResponseEntity.ok().cacheControl(CacheControl.noStore()).body(Map.of("status","ok","version", Optional.ofNullable(System.getenv("VERSION")).orElse("0.0.0-local"))); }` (do not rely on Actuator's `/actuator/health`: it has no version) |
| Static frontend served by nginx (curated `react-vite`) | the template's `nginx.conf` | already served; nothing to add |

Also add a unit test in the project's own test framework when one exists (the Next.js example mocks `next/server`'s `connection`), and a README line. The route is the app's: a human reviews it in the onboarding pull request like every other file.
