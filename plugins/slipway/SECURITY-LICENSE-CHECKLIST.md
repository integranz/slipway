## Security
- [x] (2026-09-16) No credentials, tokens or tenant identifiers committed anywhere in the repository: `git ls-files | xargs grep` for token shapes (AWS, GitHub, Slack, JWT, private keys, `client_secret =`, `password =`) and for the subscription/tenant/client GUIDs → no hits outside the guard's own test fixtures and docs. Enforced going forward by `guard-secrets-and-state.sh`; `.slipway/config.yaml` keeps `subscription_id`/`tenant_id` optional.
- [x] (2026-09-14) Every hook fails closed (parse error → block, missing `jq`/`python3` → block) and the only bypass for `terraform apply` is a human-created, single-use, 10-minute approval token (`docs/HOOKS.md`).
- [x] (2026-09-16) MCP servers in `.mcp.json` use OAuth 2.1 (Atlassian Rovo MCP, GitHub) or the user's `az login` (Azure); no static secrets in the file; Azure server started `--read-only`; explore/verify sub-agents blocked from MCP write tools by `guard-readonly-agents.sh`.
- [x] (2026-09-16) Shell scripts: `bash -n` on every script locally and in CI; `shellcheck -S warning` runs in `plugin-ci.yml` (added 2026-09-16; local machine has no shellcheck).
- [x] (2026-09-16) Dependencies: the plugin has **no runtime npm dependencies** (vendored `js-yaml` 4.3.2 MIT + a generated ajv standalone validator, see `scripts/lib/VENDORED.md`); `npm audit --omit=dev` → 0 vulnerabilities. Dev dependencies (semantic-release toolchain, ajv, js-yaml) are used only in the marketplace repo's CI.
- [x] (2026-09-16) Data handling reviewed (`README.md`): the plugin reads `.slipway/config.yaml` and repository files; network calls go only to the MCP servers the user enables and the CLIs the user has authenticated (`az`, `gh`, `terraform`, `docker`); nothing is sent to any other endpoint (grep of the plugin for URLs: `api.githubcopilot.com`, `mcp.atlassian.com`, `github.com`).
- [x] (2026-09-14) Generated Dockerfiles use distroless, non-root Docker Hardened Images; no `RUN` in runtime stages; no secrets baked into images (guard hook + `.dockerignore`).
